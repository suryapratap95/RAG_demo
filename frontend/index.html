RAG Demo Retrieval-Augmented Generation, step by step

The knowledge base. RAG lets an LLM answer from your data instead of only its training data. Here we have two kinds of source: unstructured documents (store policies) and structured SQL tables (products, customers, orders). The pipeline is: chunk → embed → retrieve → re-rank → generate.

Documents

SQL tables

Chunking splits data into pieces small enough to embed and to fit in a prompt, but big enough to keep meaning. Docs: fixed_size cuts every N characters (may cut sentences), sentence groups whole sentences, paragraph follows the document's headings. SQL: row turns each row into a sentence, entity JOINs tables so one chunk = one customer with all their orders, schema describes each table (used for text-to-SQL).
Embedding turns text into a list of numbers (a vector). Texts with similar meaning get vectors pointing the same way, measured with cosine similarity (1 = same, 0 = unrelated). TF-IDF only matches shared words; MiniLM is a neural model that matches meaning. Try it: "send back" vs "return".

Retrieval finds the top-N chunks for a question. dense = cosine similarity of embeddings, bm25 = keyword scoring, hybrid = merges both rankings with Reciprocal Rank Fusion, kmeans = only searches the cluster whose centre is closest to the question (fast on big data, but can miss answers in other clusters).
Re-ranking takes the N retrieved candidates and keeps the best K for the prompt. mmr balances relevance against repeating what is already picked, kmeans clusters the candidates and keeps the best from each cluster (diversity), cross_encoder is a model that reads question + chunk together and scores the pair (most accurate, slowest).

Generation. The re-ranked chunks are pasted into a prompt and sent to an OpenAI model on Azure AI Foundry, which answers using only that context and cites the chunks. Without Azure keys you still see the exact prompt.
RAG over your own file. Upload a PDF, Word (.docx) or text file. The same pipeline runs on it: extract text (page by page for PDFs) → chunk → embed → retrieve → re-rank → answer with citations. Uploads stay in server memory only and are cleared when the server restarts. Scanned PDFs (images of text) need OCR and won't work.
